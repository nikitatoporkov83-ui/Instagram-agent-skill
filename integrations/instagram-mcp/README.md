# Instagram MCP — помощник insta.studio на русском

Отдельный модуль публикаций, Reels, комментариев и аналитики Instagram.
Основан на загруженных владельцем исходниках William Gao, MIT.
Оригинальные материалы сохранены в `README.upstream.md`, `SECURITY.upstream.md`
и `server.upstream.json`; `PROVENANCE.json` содержит контрольные суммы загрузок.

Помощник отвечает по-русски. Описания инструментов, параметры, ошибки,
подтверждения и журнал переведены. Идентификаторы API остаются совместимыми
с исходным сервером; реальные подписи, комментарии и числа не подменяются.
MCP предоставляет инструменты, а текст ответов готовит модель в вашем клиенте.

## Возможности

- Профиль, публикации, комментарии и доступная статистика аккаунта.
- Подготовка фото, видео, Reels и каруселей.
- Подготовка ответов, комментариев и действий модерации.
- Предпросмотр и отдельное подтверждение перед изменением Instagram.
- Журнал за 30 дней: ожидает подтверждения, выполняется, выполнено, ошибка,
  неопределённый результат или отмена. Повтор подтверждения не повторяет отправку.
- Передача Reels в очередь веб-студии через `prepare_studio_reel`.

Личные сообщения включаются отдельно и требуют расширенных прав Meta.
Facebook Discovery и хештеги требуют дополнительного Facebook Graph подключения.
Сроки и доступность определяет Meta; наличие кода не подтверждает доступ к аккаунту.

## Установка и проверка

Из корня репозитория:

```bash
python3 -m venv integrations/instagram-mcp/.venv
integrations/instagram-mcp/.venv/bin/python -m pip install -r integrations/instagram-mcp/requirements.lock
integrations/instagram-mcp/.venv/bin/python -m pip install --no-deps -e integrations/instagram-mcp
python3 integrations/instagram-mcp/run.py --check
integrations/instagram-mcp/.venv/bin/python -m pytest -q integrations/instagram-mcp/tests
```

Сервер использует stdio. `run.py` запускает русскую оболочку, настраивает локальную
папку журнала и сохраняет чистый JSON-RPC в stdout. Само добавление файлов не
подключает инструменты к уже открытому чату. Настройки клиента находятся рядом
с модулем; после их добавления откройте новый сеанс клиента.

## Официальный доступ

Для прямого MCP нужен `INSTAGRAM_ACCESS_TOKEN`. Получите его через собственное
приложение Meta для профессионального аккаунта. Выберите режим, соответствующий
реальному разделу панели Meta:

| Настройка | Instagram Login | Unified Login |
| --- | --- | --- |
| `INSTAGRAM_LOGIN_MODE` | `instagram` (по умолчанию) | `unified` |
| Хост API и разрешённое назначение секрета | `graph.instagram.com` | `graph.facebook.com` |
| `INSTAGRAM_IG_USER_ID` | Необязательно | Числовой ID Instagram-аккаунта из панели Meta |
| Права для публикаций и комментариев | `instagram_business_basic`, `instagram_business_content_publish`, `instagram_business_manage_comments` | `instagram_basic`, `instagram_content_publish`, `instagram_manage_comments` |

В Unified Login все собственные публикации адресуются явно выбранному Instagram
ID. Использовать Facebook `/me` для определения целевого Instagram нельзя.
MCP не определяет тип входа по содержимому секретной переменной и не пересылает
токен на другой хост после ошибки. Режим и назначения секрета задаются владельцем.
Если вы используете оба режима, разрешите секрету оба указанных хоста.

Документация Meta: [сравнение трёх способов подключения](https://developers.facebook.com/documentation/instagram-platform/overview),
[Unified Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login).

Сохраните значение токена только в защищённых настройках среды.
Логин и пароль Instagram модулю не нужны. `INSTAGRAM_APP_SECRET` не заменяет
токен доступа. Прямой MCP не требует размещения Cloudflare Worker.

`validate_access_token` проверяет настоящий профиль. До успешной проверки
не считайте аккаунт подключённым. Не передавайте токены в чат, Git или .env.
В русской оболочке инструменты, возвращающие или записывающие токен, не доступны.

Ошибка `190` означает отказ в авторизации; сама по себе она не доказывает
истечение токена или ошибку копирования. Например, токен Unified Login и запрос
в API Instagram Login — несовместимое сочетание. Успешный вход подтверждается
реальным ответом `validate_access_token`, а не префиксом токена или тестами.

Для отправки через сайт дополнительно нужен настроенный API студии и официальный
вход владельца в веб-интерфейсе. См. корневой `INSTAGRAM_SETUP_RU.md`.
`APIFY_API_TOKEN` используется только для защищённой ссылки на запрос из чата.

## Как публиковать и отвечать

1. Вызовите `publish_reel` с видео и подписью или `reply_to_comment` с ID и ответом.
2. Помощник покажет аккаунт, материал или точный ответ и дождётся вашего согласия.
3. `confirm_action` выполнит именно проверенное действие. Предпросмотр действует
   10 минут; смена аккаунта делает подтверждение недействительным.
4. `get_action_history` и `get_action_status` покажут результат, ID и ссылку,
   если Meta её вернула. `cancel_action` отменяет ещё не отправленное действие.

При неопределённом ответе Meta проверьте Instagram перед новой отправкой.
Сервер не повторяет изменяющие запросы автоматически. Публикации, сделанные
напрямую через MCP, отображаются в его журнале; отправки через веб-студию —
в журнале сайта. Для единой истории публикаций используйте `prepare_studio_reel`.

Пример запроса: «Подготовь ответ на комментарий по-русски, покажи мне текст и
отправь после моего подтверждения». Инструкции и ответы не содержат придуманного
успеха авторизации, метрик или обещаний от лица владельца.
