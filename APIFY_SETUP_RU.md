# Apify и подборка Reels по #gta6

В студии откройте **Студия контента → Разбор Reels**. Блок Apify принимает
готовые выгрузки Instagram, показывает описания, просмотры, лайки, комментарии
и ссылки на ролики. Можно отметить до 20 записей и скачать подборку Markdown.
Импорт сам по себе не подтверждает качество хука: первая строка подписи может
отличаться от первых секунд видео. Отсутствующие метрики не заменяются нулями.

## Импорт файла — работает без сервера и ключей

1. В [Apify Console](https://console.apify.com/) откройте готовый Dataset.
2. Выберите **Export → JSON** и скачайте выгрузку.
3. В студии нажмите **Импорт JSON** и выберите файл до 5 МБ.
4. Посмотрите ролики по ссылкам, отметьте подходящие и скачайте подборку.

Поддерживаются типичные поля Instagram Actors: `shortCode`, `url`, `caption`,
`ownerUsername`, `videoPlayCount`/`videoViewCount`, `likesCount`, `commentsCount`,
`videoUrl`. Неизвестная структура может потребовать адаптации. Из файла берутся
первые 200 записей; фотографии и дубликаты исключаются. Ссылки на MP4 из CDN
Instagram могут истекать. Медиа не публикуется и не загружается автоматически.

Кнопка **В разбор Reels** передаёт записи с известным числом подписчиков или
медианой аккаунта в существующий анализатор. Без этой базы относительный
результат не вычисляется. Для русских подписей числовые данные сохраняются,
а неподдерживаемая оценка английского хука пропускается.

## Сбор из облачной среды Codex

Для клиентов Codex, которые загружают настройки доверенного проекта, в
`.codex/config.toml` сохранён точный MCP URL:

```text
https://mcp.apify.com/?tools=actors,docs,apify/instagram-scraper
```

Наличие этого файла не устанавливает коннектор в аккаунт веб-чата. В управляемой
облачной среде глобальный профиль Codex может быть защищён от записи и не
подхватывать проектные MCP-серверы. Подключение считается активным только после
OAuth в фактическом клиенте и появления инструментов Apify в текущем чате.
Сетевой доступ к `mcp.apify.com` добавлен в черновик настроек среды; он также
требует сохранения и активации пользователем.

В настройках среды добавлено требование секрета `APIFY_API_TOKEN` с доступом
только к `api.apify.com`. Значение вводится в защищённом поле, не в чат,
Git или аргументы команды. Токен, уже попавший в переписку, следует отозвать
в Apify и заменить новым.

Сохранённый черновик не меняет работающую среду. После ввода нового токена
сохраните настройки и опубликуйте среду в Codex. Сетевые требования включают
API Apify и CDN Instagram для последующей проверки видео.

Проверить параметры, ничего не запуская:

```bash
python3 scripts/apify_reels.py
```

Явно запустить ограниченный сбор публичного #gta6:

```bash
python3 scripts/apify_reels.py --start --hashtag gta6 --count 20
```

Используется официальный Actor `apify/instagram-hashtag-scraper`, до 80 записей
для отбора 20 роликов, максимум 300 секунд и 512 МБ памяти. Передаётся параметр
Apify `maxTotalChargeUsd=1`; он ограничивает списание у Actors с оплатой за
события и не является универсальной гарантией цены для других тарифов.
Actor может вернуть фотографии и записи без достаточного контекста; количество
пригодных видео зависит от источника. Живой запуск требует действующего токена,
доступного Actor и средств Apify. Его схема и ответы проверяются при реальном
подключении; эмулятор не доказывает работоспособность внешнего сбора.

Скрипт не повторяет запрос запуска после неоднозначной сетевой ошибки. Для
продолжения используйте ID из Apify Console, не создавая новый запуск:

```bash
python3 scripts/apify_reels.py --run RUN_ID
python3 scripts/apify_reels.py --dataset DATASET_ID
```

Результаты сохраняются в `.instagram/research/gta6/`, которая исключена из Git.
`gta6-candidates.json` содержит только разрешённые поля роликов. Присутствует
отдельный флаг `videoHookReviewed: false`: автоматическая оценка относится к
английской строке подписи, а окончательный отбор требует просмотра видео.
Этот JSON можно сразу импортировать в сайт.

## Онлайн-импорт на сайте

GitHub Pages не хранит серверные секреты. Для онлайн-импорта подготовлен отдельный
Cloudflare Worker без Meta-приложения и базы данных; можно также использовать
уже существующий Worker подключения Instagram.

В Cloudflare создайте Worker из `backend/wrangler.apify.toml` и задайте:

- `SITE_URL` — полный адрес сайта, уже указан для этого репозитория.
- `APIFY_API_TOKEN` — секрет Apify с доступом к нужным Dataset/Run/Actor.
- `APIFY_ACCESS_KEY` — отдельный случайный код студии длиной от 32 до 256 символов.

Секреты вводятся через настройки Worker либо интерактивные команды, без значения
в командной строке:

```bash
cd backend
npx wrangler secret put APIFY_API_TOKEN --config wrangler.apify.toml
npx wrangler secret put APIFY_ACCESS_KEY --config wrangler.apify.toml
npm run deploy:apify
```

После размещения укажите HTTPS-origin Worker в `apifyApiUrl` файла
`web/integration-config.js`. Это публичный адрес, ключи туда не добавляются.
Проверка `/api/apify/status` должна сообщать `configured: true`.

В студии введите ссылку на Dataset, Run или Actor и код `APIFY_ACCESS_KEY`.
Код остаётся только в памяти вкладки; провайдерский токен браузеру не выдаётся.
Онлайн-импорт делает только GET-запросы к готовым результатам; платный запуск
Actor выполняется отдельно. Для Actor берётся последний успешный запуск.

Доступ к Apify никак не означает вход в Instagram. Публикации по-прежнему
требуют отдельного подключения и явного подтверждения.

## Проверки разработки

```bash
python3 scripts/build_site.py
python3 -m unittest discover -s tests -v
npm test --prefix backend
npm run check:apify --prefix backend
python3 scripts/check_apify_browser.py
```

Backend и браузерные проверки используют явно тестовые записи; они не запускают
платный Actor и не собирают реальные Reels. Отдельная проверка живого подключения
выполняется после настройки токена и разрешений среды.
